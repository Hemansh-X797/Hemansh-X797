# How this repo works

Nothing on the rendered profile page is hand-drawn or hand-typed except the
words in `scripts/hero.py`'s `CONTENT` dict and the entries in `data/*.json`.
The portrait, hero banner, stat numbers, project cards, and skill radars are
generated by scripts in `scripts/` and committed by a GitHub Action -- no
dependency on a third-party card-generator staying up. The isocalendar,
coding-habits, language-breakdown, and achievements panels come from
`lowlighter/metrics`, a real widely-used Action (not something built here) --
that one's a Docker action, so it can't be run as a local script.

## One-time setup after you push this repo

1. **Push to `Hemansh-X797/Hemansh-X797`.** GitHub only turns a repo into a
   profile README if it's named exactly `<username>/<username>` and public.
2. **Settings -> Actions -> General -> Workflow permissions** -> set to
   *"Read and write permissions"*. The workflows commit generated SVGs back
   to `main`, so the default `GITHUB_TOKEN` needs write access.
3. **Add a `METRICS_TOKEN` secret** (Settings -> Secrets and variables ->
   Actions -> New repository secret). Classic PAT, scope `read:user`. This
   is only for `metrics.yml` (isometric calendar + coding habits need to
   read your contribution graph, which the built-in `GITHUB_TOKEN` can't
   see). Without it, `metrics.yml` still runs on the `GITHUB_TOKEN` fallback
   -- languages/achievements work, isocalendar/habits come back empty.
4. **Run each workflow once manually** (Actions tab -> select workflow ->
   *Run workflow*), in this order:
   - `rebuild hero + portrait` — only needed once, or after you change the
     photo/copy. Already committed in this drop, so you can skip this unless
     you're changing something.
   - `refresh live cards` — pulls your live stats, project stars, languages,
     and both radars. **Run this first thing**, since the repo ships without
     `assets/card-*.svg` / `assets/projects-*.svg` / `assets/radar-langs-*.svg`
     (shipping fabricated numbers would be worse than a placeholder-free
     first run).
   - `metrics` — builds the isocalendar, coding habits, language breakdown,
     and achievements panels.
   - `snake` — builds the contribution graph animation.
5. After that: `refresh` runs daily + on every push to `main`; `metrics`
   runs every 6 hours; `snake` runs daily. You don't need to touch them again.

## About V.I.N.C.E. and Hyperion

Right now `data/projects.json` lists all four projects, but the GitHub API
can only see the ones it has access to. If a repo is private, or the API
call 404s for any reason, `fetch_data.py` marks it `"unavailable": true`
instead of guessing — and `generate_projects.py` renders that card with a
lock badge and *no* star/fork/language numbers, rather than making them up.

**When you're ready to make V.I.N.C.E. and/or Hyperion public**, nothing in
this repo needs to change — the next scheduled `refresh` run (or a manual
one) will pick them up automatically and switch the card over to live stats.

## Editing things yourself

| Want to change...            | Edit this                                  | Then run |
|---|---|---|
| Bio, role, tagline, stack pills, "currently building" line | `scripts/hero.py` -> `CONTENT` dict | `rebuild hero + portrait` workflow |
| Which photo / which crop | `assets/hemansh-face-source.png`, `--focus x,y` in `media.yml` | `rebuild hero + portrait` workflow |
| Self-rated skills | `data/skills.json` | `refresh` workflow (radar step) |
| Live language radar (which repos count) | `--exclude` / `--limit` flags in `refresh.yml`'s language-radar step | `refresh` workflow |
| Project list, descriptions, taglines | `data/projects.json` | `refresh` workflow |
| Project logos | drop `<reponame-lowercase>.png` (or `.svg`) into `logos/` | `refresh` workflow |
| Coding habits / isocalendar / achievements | flags in `metrics.yml` | `metrics` workflow |
| Palette | the `THEMES` dict at the top of `hero.py` / `cards.py` / `radar.py` / `generate_projects.py` | whichever workflow touches that file |

`data/skills.json` and `data/projects.json` both have a `"comment"` key at
the top explaining the fields — read that before editing.

## Running scripts locally

```bash
pip install Pillow

# portrait / hero (no network needed)
python3 scripts/dotify.py assets/hemansh-face-source.png -o assets/portrait \
  --cols 130 --square --focus 0.5,0.35 --detail 0.6 --contrast 1.35 \
  --color --invert --circle --reveal

python3 scripts/hero.py --photo assets/hemansh-face-source.png --focus 0.5,0.35 -o assets

# radar (no network needed)
python3 scripts/radar.py --data data/skills.json -o assets/radar

# live language radar (needs a token to see private repos)
export GITHUB_TOKEN=ghp_xxx
python3 scripts/radar.py --github Hemansh-X797 -o assets/radar-langs --limit 6

# stats + project cards (needs a token for contribution/streak numbers;
# works without one too, just renders fewer tiles)
python3 scripts/cards.py --user Hemansh-X797 --out assets
python3 scripts/fetch_data.py --owner Hemansh-X797
python3 scripts/generate_projects.py data/merged.json assets logos
```

`metrics.yml`'s four panels (isocalendar, habits, languages, achievements)
only run as a GitHub Action -- `lowlighter/metrics` is a Docker action, not
a local script, so there's nothing to run locally for those.

A token needs no special scopes for public data — a plain
`read:user, public_repo` classic token, or a fine-grained token with
read-only access to your own account, is enough. In Actions, the built-in
`secrets.GITHUB_TOKEN` already covers this; you don't need to create
anything.

## Why no JS-interactive widgets (kernel visualizer, live chat, etc.)

GitHub strips `<script>` tags and disables interactivity in anything
rendered through an `<img>` tag, which is how every image in a profile
README gets loaded — so nothing genuinely interactive (a kernel scheduler
you can click through, a RAG chatbot, an audio-reactive HUD wired to a live
Spotify session) can actually run on this page, no matter how it's built.
Everything here uses SMIL (`<animate>`) instead, which *is* allowed and
does run — that's what's driving the typing effect, the pulsing dots, the
radar draw-in, and the reveal sweep on the portrait.

If you want the real version of those ideas (a clickable OS-scheduler demo,
etc.), that has to live on a separate page — e.g. GitHub Pages — with the
README linking to it. That's a genuinely different project, not a tweak to
this one; say the word if you want it scoped out.
